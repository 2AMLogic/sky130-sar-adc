Dated 2026-10-27. Runs used a throwaway venv (`pip install klayout-tools==0.8.0`,
`klt --version` printed `klt 0.8.0`); single-unit runs only, no SPICE.

## Signoff grading (0.6.0 -> 0.8.0)

`klt signoff --manifest signoff/block-manifest.json --check` under 0.8.0 on the
unchanged 0.6.0-era report: `status: match`, `doc_drift: true` (checklist
wording only). `signoff/t1-report.json` was then re-rendered. Comparing the old
and new report item by item, every field other than `text`/`notes` is equal
(25 items, same ids); the top-level fields other than `build`, `items` and
`source_doc_content_hash` are equal. Changed: `build` (0.8.0, `v0.8.0`),
`grading_ruleset_id` `sha256:0d8cc27c...` -> `sha256:46c446d8...`,
`source_doc_content_hash` `sha256:63eeec72...` -> `sha256:a26b9026...`, and
descriptive text. `signoff/check_evidence_hashes.py` still passes.
`signoff/evidence/characterization-report.generic.json` was not regenerated:
the `--check` above passes with it unchanged.

## `sim/yield-requirements.txt`

Not a batch-runner pin (its header concerns resolvability). The string moved to

`klt-yield-native<0.2,>=0.1.0`; I did not test whether it resolves, so the file's

## `supply_v` audit (klayout-tools#2867)

Scope: the 17 committed `sim/**/request*.json` files. Every `corners.supply_v`
dict key in them is `vdig` (351 occurrences) and the netlists they reference
contain a voltage source `Vdig` (`Vdig VPWR 0 DC 1.8`; checked by grep, not by
running `klt sim`). Zero keys found that do not name a voltage source. The other
`"supply_v"` hits in `.py` harness files are Python dict keys, not klt request
keys; those were not individually audited. No SPICE was run.
