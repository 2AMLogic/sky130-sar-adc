## Disposition

- No spec line was touched or relaxed; no local deck edits.
- Nothing is dispositioned as "waive". The five non-ongrid families are findings that 0.6.0 could not see;
  four (`via.5a`, `m2.5`, `poly.8`, `via3.1`) measure as real drawn geometry in klt-generated cells and the router's
  pads. Fixing them is layout/generator work (cell regeneration, pad sizing, re-run of every flow) and was not done here.
- `layout/requirements.txt` therefore **stays at 0.6.0**; the acceptance step "bump once clean or dispositions are
  recorded" is not met, so no flow was re-run and no `reports/<ts>-<sha>` was minted.
- No new `klayout-tools` issue filed: the classes above are already tracked (#3316, #3413, #2936, all closed and
  shipped). Open question for the tool side, if the `via2.5` layer is confirmed as m3 in the DRM: the rule id/description
  `met2.enclosing_adjacent.via2.1` would then be checking a different layer than the DRM text.
