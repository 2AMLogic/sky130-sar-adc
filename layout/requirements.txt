# Pinned klayout-tools (`klt`) install for layout/'s DRC/LVS flow (issue #2).
#
# klt v0.2.0 on PyPI (https://pypi.org/project/klayout-tools) ships the
# gen/drc/extract/lvs/draw verbs this flow needs -- unlike
# 2AMLogic/sky130-bandgap's requirements.txt at the time it was written
# (issue #14 there), which had to pin a git commit because those verbs
# were only on `main`. Pinning the PyPI release here instead of a git SHA
# is simpler and reproducible the same way: an exact version, not a
# floating one.
#
# Provenance: pattern (pin-and-document-why, `--force-reinstall` discipline
# in layout/bin/setup-venv.sh) ported from 2AMLogic/sky130-bandgap's
# layout/requirements.txt (commit 1f04e8524cc2d8c2c7154773749b1b2d3be2ce64),
# per CLAUDE.md's "Harness bootstrap" instruction.
#
# Bumped 0.2.0 -> 0.3.0 for issue #101 (comparator sub-block layout): `klt
# gen-compose`'s 0.2.0 build only routes strictly 2-pin connectivity[] nets
# (a 3+-pin net -- e.g. this block's VDD/GND/OUTP/OUTN rails, each touching
# 3-8 device terminals -- comes back in unrouted_nets[] with no metal drawn).
# 0.3.0 adds bundle (>2-pin) routing as a spanning tree of two-pin legs
# (2AMLogic/klayout-tools#1094/#1073), which the comparator's own supply/
# output rails need directly -- not a hand-authored-netlist need, a real gap
# hit doing this sub-block's layout. No klt gap filed for this one: the
# capability already exists in a released version newer than the prior pin,
# so it is a pin bump, not a tool-tracker friction report.
#
# Independently required by issue #100 (CDAC array layout): 0.2.0's sky130
# extraction deck stops its metals/vias connectivity at met1, so a MiM-cap
# array with bottom plates on met3 and top-plate rails on met4 is not
# extractable on that pin at all. 0.3.0's met2-met5/via2-via4 connectivity
# is what makes the array's `klt extract`/`klt lvs` verdicts possible.
klayout-tools==0.3.0
