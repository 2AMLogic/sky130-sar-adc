## Deck divergences from the per-corner reference method

Each is a consequence of one shared deck body with the corner applied as an axis, not a change of mechanism:

- **Margin helper sources.** each measured node gets a testbench-only behavioural source `Bm_<node>` whose output is the node's signed distance from half the rail (`v(node) - 0.5*v(VPWR)`), and each `.meas` card samples that helper's node. A `klt sim` limit is a static number, so this is how the request expresses the runner's actual decision rule (a sample above half the RAIL -- 0.81/0.90/0.99 V across the axis -- is a one) instead of a fixed volt threshold. The helpers drive nothing and load nothing; the DUT and stimulus are unmodified.
- **Supply as a parameter axis.** the per-corner deck rewrite set `.param vdd_val = <supply>` per point; the shared body declares `.param vdd_val = 1.8` and `corners.params` sets it per corner via `alterparam` + `reset`, which re-evaluates every `{vdd_val}` expression (rail source and the rail-referenced CLK/RST_B/COMP_OUT stimulus together). `corners.supply_v` cannot be used here: it `alter`s a source instance, and klt refuses that for a PWL/PULSE source.
- **Standard-cell library include.** `$PDK_ROOT/sky130A/libs.ref/sky130_fd_sc_hd/spice/sky130_fd_sc_hd.spice`, expanded by the executing worker against its own PDK_ROOT (the same spelling sim/digital-partition/ uses), in place of the per-corner deck's absolute path into this checkout's PDK.
- **Netlisting via `klt netlist`.** the DUT is netlisted with `klt netlist` (which owns the xschem invocation, its headless flags and its timeout) instead of the harness's direct xschem call. Only `.end` and the two checkout-path-bearing `**`-comment header lines are dropped from the embedded text; device content is byte-identical, and the inert `**.subckt` wrapper comment xschem writes is left in place -- every record of this campaign since August graded that same flat form.
- **Deck mechanics owned by the request.** `.options num_threads=1` (one solver thread per unit), the `.tran` arguments, and the `.meas` cards moved from the fragment into the request's `analysis`/`measurements` fields -- `klt sim` owns the `.control` wrapper. The fragment's device cards are used verbatim.
