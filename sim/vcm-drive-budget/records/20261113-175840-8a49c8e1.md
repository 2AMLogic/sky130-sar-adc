## C_decouple budget for <= 1 provisional LSB of differential error, per corner

"Budget" is the LAST (largest, in ascending sweep order) swept NONZERO C_decouple for which `abs(diff_err_lsb) <= 1.0` still holds at that corner's own marginal R_source -- see `find_budget()` in this script, the same convention the bare R_source full-grid records already use, applied to the C_decouple axis here. The C_decouple = 0 control row is excluded: it is the row every other row's error is measured against, so its own error is identically zero and reporting it would state a "budget" of 0 pF for a sweep in which no capacitor actually worked. It is **not** necessarily the smallest sufficient C_decouple, and larger values are not guaranteed to also work: the single-corner seed record's own C_decouple sweep already found this error is **not** monotonic in C_decouple (a bigger cap lengthens the same node's settling time constant as much as it stiffens its DC impedance). A budget equal to the largest swept value (1000 pF) is right-censored. "None found" means no swept nonzero C_decouple value, at that corner's own marginal R_source, keeps the error within 1 LSB -- decoupling alone does not rescue that corner within the swept range. A marginal R_source marked **(fallback)** is NOT a marginal case: no swept bare R_source at that corner exceeded 1 provisional LSB, so `marginal_r_source()` fell back to the largest swept value and the C_decouple sweep there was run against a resistance that was not failing on its own. Those corners had nothing for decoupling to rescue, and their budget column is reported but not counted as a rescue in the Result section below.

## Result

- **9 of 9 ratified corners had nothing for decoupling to rescue** (`tt_27c_1.80v`, `ss_27c_1.80v`, `ff_27c_1.80v`, `sf_27c_1.80v`, `fs_27c_1.80v`, `tt_-40c_1.80v`, `tt_125c_1.80v`, `tt_27c_1.62v`, `tt_27c_1.98v`): no swept bare R_source at those corners pushed the differential error past 1 provisional LSB, so `marginal_r_source()` fell back to the largest swept value (100000 ohm) and the C_decouple sweep there measured a resistance that was not failing on its own. Whatever their budget column says, those corners are **not** evidence that decoupling rescues anything, and they are excluded from the rescue counts below.
- **No ratified corner's bare R_source sweep failed at all**, so this campaign establishes nothing about whether decoupling rescues this mechanism: every corner's C_decouple sweep ran against a fallback resistance that was already inside 1 provisional LSB undecoupled. A C_decouple campaign that can answer the rescue question needs a bare sweep that reaches a failing R_source at each corner first.
- The per-corner marginal R_source values in the table above are themselves re-derived from each corner's own bare sweep in this same invocation, and reproduce the bare R_source full-grid campaign's own per-corner shape ([`records/20260907-052526-f589273.md`](20260907-052526-f589273.md)) rather than assuming the tt/27C/1.8V value applies everywhere.
- This campaign repeats ONLY the C_decouple sweep at the legacy (400.0 ns) testbench convention window. The DR-006 worst-case (12 MHz, 83.333 ns) window's own C_decouple sweep remains single-corner (tt/27C/1.8V) only; a full-grid pass over it is a natural next step, the same one-window-per-pass precedent this mechanism's own bare R_source full-grid campaigns already established. It does not, on its own, establish what R_source/C_decouple an actual on-chip VCM buffer or off-chip reference network would present -- no such buffer exists in this design yet (docs/chipalooza/challenge-4-proposal.md Section 2.2).

## Uncontrolled differences against the record this supersedes

- **PDK commit and simulator version.** [`records/20260908-115336-f3e2914.md`](20260908-115336-f3e2914.md) was minted on `sky130A @ c6d73a35f524070e85faff4a6a9eef49553ebc2b` / `ngspice-46` (read from that record's own Environment block); this record was produced on `sky130A @ f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7` / `ngspice-47`. **Those differ.** Any change in a figure between the two records is as readily a PDK or simulator-version difference as a circuit or harness one; nothing here is a controlled comparison against that record, and no figure in it is corrected by this one.
- **Execution route.** The superseded record's grid was solved by an in-process `ngspice` loop on the submitting host, one subprocess per (corner, swept value). This record's grid is ONE `klt sim` request executed by the batch fleet (block above), one unit per corner, with each swept value an `analysis_steps[]` entry inside that unit. The numbers therefore come from a different machine, a different scheduler and a different deck-assembly path than the record it supersedes.
- **Submitting host vs. executing worker.** The Environment block below names the PDK and ngspice of the EXECUTING worker when it reported them; the submitting host resolved `sky130A @ f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7` / `ngspice-47`. They are the same for this run.
- **Deck changes made by the port itself** (issue #881) -- each is a consequence of one shared deck body with the corner applied as an axis, not a change of mechanism:
  - **Supply-tracking `VCM` source.** The per-corner deck wrote `VCM`'s ideal level as a literal (`dc {vdd * VCM_FRAC}`) because it regenerated a deck per corner. One shared body cannot, so `VCM_IDEAL` is driven by a behavioural source `Bvcm VCM_IDEAL 0 V=v(VDD)*VCM_FRAC`, which evaluates to the same level at every corner the grid runs.
  - **Supply-tracking `SAMPLE` source.** Likewise `pulse(0 {vdd} ...)` becomes a NORMALISED 0..1 `pulse` on `SMP_CTL` scaled by the corner's own supply through `Bsample SAMPLE 0 V=v(SMP_CTL)*v(VDD)` -- the same device `sim/input-drive-budget/run_input_drive_budget.py` uses for its own SAMPLE control, and for the same reason.
  - **The supply source is named `vsup`.** `klt sim` applies the `corners.supply_v` axis as a literal `alter <key>=<value>`, so the key is the element name; the per-corner deck called it `Vdd`.
  - **The `C_decouple = 0` control row is a 1 aF capacitor, not an omitted card.** A step can only `alter` a card the shared body already carries, so `Cdecouple` is present in every step (see `C_IDEAL_F`). The per-corner deck omitted it entirely at `C_decouple = 0`.
  - **`.options num_threads=1`.** Added so a multi-core fleet worker solves the deck the same way a single-threaded local run does; the per-corner deck carried no `.options` card.
