## Bare R_source budget for <= 1 provisional LSB of differential error, per corner

"Budget" is the largest swept NONZERO R_source (ohm) at which `abs(diff_err_lsb) <= 1.0` still holds at that corner -- see `find_budget()` in this script. The R_source = 0 control row is excluded: it is the row every other row's error is measured against, so its own error is identically zero and reporting it would state a "budget" of 0 ohm for a sweep in which no source resistance actually worked. "none (< smallest nonzero tested)" means the smallest nonzero swept value (10000 ohm) already exceeds the tier -- that corner allows **zero** margin for any nonzero drive impedance, which is a TIGHTER result than any number in this column, not a missing measurement. A budget equal to the largest swept value (100000 ohm) is right-censored: every swept value stayed under threshold, so the true budget is >= that value, not necessarily equal to it.

- **PDK commit and simulator version.** [`records/20260908-101358-f3e2914.md`](20260908-101358-f3e2914.md) was minted on `sky130A @ c6d73a35f524070e85faff4a6a9eef49553ebc2b` / `ngspice-46` (read from that record's own Environment block); this record was produced on `sky130A @ f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7` / `ngspice-47`. **Those differ.** Any change in a figure between the two records is as readily a PDK or simulator-version difference as a circuit or harness one; nothing here is a controlled comparison against that record, and no figure in it is corrected by this one.
- **Execution route.** The superseded record's grid was solved by an in-process `ngspice` loop on the submitting host, one subprocess per (corner, swept value). This record's grid is ONE `klt sim` request executed by the batch fleet (block above), one unit per corner, with each swept value an `analysis_steps[]` entry inside that unit. The numbers therefore come from a different machine, a different scheduler and a different deck-assembly path than the record it supersedes.
- **Submitting host vs. executing worker.** The Environment block below names the PDK and ngspice of the EXECUTING worker when it reported them; the submitting host resolved `sky130A @ f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7` / `ngspice-47`. They are the same for this run.
- **Deck changes made by the port itself** (issue #881) -- each is a consequence of one shared deck body with the corner applied as an axis, not a change of mechanism:
  - **Supply-tracking `VCM` source.** The per-corner deck wrote `VCM`'s ideal level as a literal (`dc {vdd * VCM_FRAC}`) because it regenerated a deck per corner. One shared body cannot, so `VCM_IDEAL` is driven by a behavioural source `Bvcm VCM_IDEAL 0 V=v(VDD)*VCM_FRAC`, which evaluates to the same level at every corner the grid runs.
  - **Supply-tracking `SAMPLE` source.** Likewise `pulse(0 {vdd} ...)` becomes a NORMALISED 0..1 `pulse` on `SMP_CTL` scaled by the corner's own supply through `Bsample SAMPLE 0 V=v(SMP_CTL)*v(VDD)` -- the same device `sim/input-drive-budget/run_input_drive_budget.py` uses for its own SAMPLE control, and for the same reason.
  - **The supply source is named `vsup`.** `klt sim` applies the `corners.supply_v` axis as a literal `alter <key>=<value>`, so the key is the element name; the per-corner deck called it `Vdd`.
  - **The `C_decouple = 0` control row is a 1 aF capacitor, not an omitted card.** A step can only `alter` a card the shared body already carries, so `Cdecouple` is present in every step (see `C_IDEAL_F`). The per-corner deck omitted it entirely at `C_decouple = 0`.
  - **`.options num_threads=1`.** Added so a multi-core fleet worker solves the deck the same way a single-threaded local run does; the per-corner deck carried no `.options` card.
